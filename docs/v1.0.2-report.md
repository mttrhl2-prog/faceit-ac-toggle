# v1.0.2 patch report

The existing service/MVVM architecture is retained. This patch changes scanning, runtime evidence, presentation and validation; the four groups' write contracts are retained.

## Scanner diagnosis and fix

The v1.0.1 `ProcessService` tried `Encoding.GetEncoding(CultureInfo.CurrentCulture.TextInfo.OEMCodePage)` while preparing `ProcessStartInfo`. `en-FI`, `en-150` and `en-DE` reproduced OEM code page `1` and `ArgumentException: 1 is not a supported code page`, before BCDEdit could start. This explains an app-level Error with otherwise valid BCD on affected cultures. The reported target PC's exact trigger has not been confirmed without its error log.

The patched process service retains its exact four-command allowlist and captures raw stdout/stderr concurrently. It uses `GetConsoleOutputCP` or the machine's `GetOEMCP`, then handles UTF-8/UTF-16 BOMs, BOM-less UTF-16 and OEM fallback. `HypervisorService` reads trimmed lines, splits whitespace and matches the exact key case-insensitively. Auto/Off are configured On/Off; a missing element in successful nonempty output defaults to Auto. Unexpected/malformed/duplicate elements remain Unknown; process and empty-output failures remain Error. No Windows settings are changed during scanning.

## Runtime and UI

`RuntimeStateService` queries only FACEIT and FACEIT_IOMMU names in `Win32_SystemDriver`, using Running/Stopped as separate nullable runtime values. A completed query without a matching driver means not running; a failed/transitional query remains unavailable. HVCI and hypervisor runtime remain independent of configured state.

Restart derives from configured/runtime differences in HVCI, hypervisor and either FACEIT driver. Reopening rescans those values and recovers driver restart awareness without saved toggle state. A session-only write fallback remains for uncomparable groups (including the blocklist) and is removed for groups with fresh comparable runtime evidence. There is no claimed blocklist effective-state API or persisted blind flag.

Only the matching Enabled/Disabled card is highlighted; Custom highlights neither. The badge follows the profile, normal row labels are hidden, exceptional states remain visible and accessibility still reports state/action/error. Static restart bullets are removed. Error Detail stays in tooltip/status and Refresh retries reads.

## Verification and limits

- Linux Release cross-build: no compiler errors or warnings; self-contained win-x64 publish completed.
- Linux portable tests: 101 executed and passed, including all 42 prior tests and 59 new cases.
- Windows suite: 19 cases for ViewModels/accessibility, active profile flags, read-only retries, reopening/matching/unavailable runtime, blocklist fallback, restart cancellation, process allowlist and native read-only BCDEdit capture under en-FI. Windows results are recorded by the release workflow in `validation-results.json`; Linux cannot execute this WPF test assembly.
- Regression checks assert exact FACEIT writes and value deletion, and reject excluded tweak/shell identifiers from production source. FACEIT, Core Isolation and Driver Blocklist controllers, native RegistryService, RestartService and administrator manifest are unchanged from v1.0.1.
- No production code introduces IOMMUFlags, hypervisoriommupolicy, Credential Guard, System Guard, LsaCfgFlags, optional-feature changes, SmartScreen or Control Flow Guard. No additional write command is allowed.
- Real Windows 11/FACEIT UI, permissions, WMI/provider state, reboot and compatibility require the updated target-PC checklist. The user's tested baseline is recorded as user-provided evidence, not inferred from CI.
